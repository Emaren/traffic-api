# Traffic V2 — Ingestion Receipt Evidence and Safe Activation

## Ownership and non-goals

This document is an operational code contract, not an instruction to
publish unfinished audience data. It is separate from public website release
A05–A09 and WOLO financial release C01–C09. The legacy 131-day certified
Traffic archive remains frozen at **2026-10-19** until the separately gated
V2 classification, completeness, boundary, publication and owner controls
pass. Running an audit is **never** such approval.

The repository contains the actual insertion-time implementation in
`app/services/traffic/persistence.py`. It is intentionally dormant unless
`TRAFFIC_INGEST_RECEIPTS_ENABLED` is explicitly enabled in the **actual**
`traffic-ingest.service` process environment. New insertion times are
generated by SQLite itself. Existing rows are NOT backfilled.

## Permanent bounded audit

`scripts/public_audience_v2_ingestion_receipts_health.py` reads only a
bounded last-N SQLite ROWID sample using `mode=ro`,
`PRAGMA query_only=ON` and a short timeout. It never updates tables,
opens or copies private event payloads, restarts services or prints IPs,
user agents, full event timestamps, actor IDs or source filenames.

On the Traffic host, from the checked-out source version:

```bash
nice -n 15 timeout -k 3s 25s .venv/bin/python3 \
  -m scripts.public_audience_v2_ingestion_receipts_health \
  --source /mnt/HC_Volume_105319120/traffic-db/traffic_history.sqlite3 \
  --sample 1000 --require-receipts
```

Without `--require-receipts`, the program returns exit 0 for
**informational** status JSON even when data is missing. With the flag,
any `HOLD_*` status exits 2, suitable for CI/operator gating.
`OBSERVED_RECEIPT_SAMPLE_ONLY` is a healthy *bounded sample*, not a
publication certificate. No output state implies log-delivery finality,
global-IP classification stability, two closed days or authorization to
publish. The script intentionally does NOT check the historical archive
hash; its stated October 19 boundary is the pinned source assumption,
not an independently reverified digest.

## Activation is a separate controlled operation

**Before changing the flag or running a writer on this source:**

1. Obtain a source-consistent, independently verified recent SQLite
   backup or volume snapshot, with a clear restore path and sufficient
   off-host capacity; capture its exact immutable checksum, source
   identity, UTC point-in-time and owner/reviewer evidence. Do not assume
   the 19-GiB-free attached volume can hold a copy of this >51-GB source.
2. Qualify the exact approved Python commit plus existing insertion-clock
   tests, service account, systemd environment file mode/ownership,
   ingest timer, current source DB schema and existing WAL/journal.
   Preserve all secrets; never print `/etc/traffic-api.env`.
3. Prove the Traffic ingest worker is idle and preserve rollback for the
   **actual** service config and binary identity. Activate only the
   reviewed `TRAFFIC_INGEST_RECEIPTS_ENABLED=1` source-path flag,
   not a general public publisher or retry loop.
4. Permit exactly one guarded normal `traffic-ingest.service` cycle.
   Prove success and that `ingested_at_utc` exists, new committed
   events bear valid SQLite UTC insertion times, older rows remain NULL,
   and duplicate ignored events retain their original insertion times.
5. Re-run the bounded audit with `--require-receipts`, inspect mixed
   writer/clock violations, verify the independent 131-day certified
   archive digest with the canonical verifier, check source/WAL health,
   and watch multiple timer cycles beyond the first successful one.
6. Preserve first non-NULL insertion-row evidence. Historical rows
   lacking insertion receipts remain **left-censored** forever:
   never guess their arrival time or declare October 20 final.

If a gate fails, restore the reviewed service configuration and run the
tested recovery procedure. A nullable schema column may remain after
rollback; do not attempt a destructive 48-GiB table rewrite just to
remove it. Always record the precise failure and residual state.

## What still prevents public human-day publication

An insertion-time receipt bounds when a row reached SQLite; it **does
not** prove all remote Nginx logs have arrived. Additional independent
proofs must establish remote delivery/rotation progression and a
supported lateness contract, global-IP freeze/reclassification policy,
October 19/20 stitched actor/session continuity, independent two-day
source/parity witnesses, and guarded atomic append-only publication.
Until then, observed qualifying IPs/GET events remain in their
separately labeled provisional panel; no new certified human point is
to be invented.
